# Task Splitting

## Workflow

1. Review the original task and implementation plan.
2. Identify logical boundaries between parts of the work.
3. Break the work into smaller independent tasks.
4. Present the tasks as a sequential numbered list.
5. Ask the user which task they want to work on first.
6. Treat the selected task as the current task.

## Rules

- Keep tasks small and logically focused.
- Use only a single-level numbered list.
- Do not use nested tasks or substeps.
- Preserve the requirements of the original task.
- Do not implement any task until the user selects one.
- Do not introduce unrelated work.
