# OpenCode Workflow

## Task Intake

When a new session starts, ask:

"What's your task for today?"

Expect the user's first response to be a task description.

## Planning Before Changes

Never make code changes immediately.

After receiving a task:

1. Analyze the task.
2. Explain what needs to be changed.
3. Show a list of implementation steps.
4. Ask whether the user wants to:
   - Keep the task as-is
   - Divide it into smaller tasks

If the user chooses to divide the task, break it into smaller tasks and ask the user which task to start with.

## Before Implementation

Before making any changes:

1. Explain exactly what you are about to change.
2. Ask for confirmation.
3. Do not modify files until the user confirms.

## After Each Change

After completing a change:

1. Show a summary of what was changed.
2. Ask whether the user wants to commit the changes using gitmoji.

Repeat this process until all tasks are completed.
